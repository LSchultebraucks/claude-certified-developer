# Domain 4 — Prompt Engineering & Structured Output

### a4-crit-01
skill: 4.1
scenario: S5
Your CI review prompt says "Be conservative and only report high-confidence issues." False positives remain high, especially for "possible performance problems". What change is most effective?
- [ ] Add "be even more conservative" and ask Claude to double-check each finding before reporting it
- [x] Define explicit criteria for what to report, what to skip, and how to rate severity
- [ ] Require a confidence score on each finding and post only those with a score above 0.8
- [ ] Switch to a larger model, which will better understand what "high-confidence" means for the team
> Vague instructions give no decision boundary; explicit criteria do. Self-reported confidence is poorly calibrated; a bigger model still faces an undefined boundary.

### a4-schema-01
skill: 4.3
scenario: S6
Your extraction pipeline uses a tool with a JSON schema and a forced `tool_choice`. Outputs always parse, but some invoices have line items that don't sum to the stated total. What does this show?
- [ ] The schema is misconfigured, because a correct schema would prevent arithmetic inconsistencies
- [ ] The forced `tool_choice` causes these errors; switching to `auto` would improve accuracy
- [x] Schemas eliminate syntax and shape errors but not semantic errors, which need validation in code
- [ ] The model's temperature is too high, which causes random arithmetic errors in extraction
> Schema enforcement guarantees structure, not correctness of values. Semantic checks (sums, date order) belong in validation code. `tool_choice` and temperature aren't the cause.

### a4-schema-02
skill: 4.3
scenario: S6
Contracts sometimes lack a renewal date, but your schema marks `renewal_date` as a required string. Extractions contain plausible but invented dates. What is the best fix?
- [ ] Add "never invent dates" to the system prompt, in capital letters near the schema
- [ ] Remove `renewal_date` from the schema and extract it in a separate free-text step
- [x] Make `renewal_date` nullable and describe it as "null if the contract does not state one"
