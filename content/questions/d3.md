# Domain 3 — Claude Code

### d3-cc-01
skill: 3.1
type: single
A team has a 12-step release procedure that Claude Code should follow only when someone asks to cut a release. Where should this procedure live?
- [ ] In the project CLAUDE.md, so the procedure is always in context and never forgotten
- [x] In a skill, e.g. `.claude/skills/release/SKILL.md` with `disable-model-invocation: true`
- [ ] In `~/.claude/settings.json` under `env`, so each step is available as a variable
- [ ] In a PreToolUse hook that injects the procedure whenever Claude runs a git command
> Skills hold procedures that load on demand; disabling model invocation makes a side-effectful workflow user-triggered. CLAUDE.md is loaded every session and should stay short; settings and hooks aren't for multi-step instructions.

A CI job runs `claude -p "Fix the lint errors"` but Claude never edits any file. Logs show permission denials. What is the most likely fix?
- [ ] Describe the lint errors in more detail in the prompt so Claude knows which files to edit
- [x] Pre-approve the needed tools with `--allowedTools` or set a mode such as `acceptEdits`
- [ ] Switch to `--output-format stream-json` so permission requests are streamed to the CI log
- [ ] Use a larger model, which is allowed to edit files without explicit permission rules
> In non-interactive runs nobody can answer permission prompts, so actions that would prompt are denied. Pre-approving tools or setting a permission mode solves it; output format and model choice don't.

A script needs Claude Code's answer as machine-readable data including the session ID and cost so a later step can resume the same conversation. Which invocation fits?
- [ ] `claude "task"` in interactive mode, copying the session ID from the welcome screen
- [x] `claude -p "task" --output-format json`, then `--resume <session_id>` for the follow-up
- [ ] `claude -p "task" --output-format text` and grep the output for the session ID line
- [ ] `claude --continue` without `-p`, which prints the session metadata as JSON on exit
> JSON output includes `result`, `session_id` and cost metadata; `--resume <id>` continues that exact session. Text output doesn't include metadata; interactive commands don't suit scripts.

Which permission mode lets Claude Code explore the codebase and propose a plan without modifying source files?
- [ ] `acceptEdits`
- [x] `plan`
- [ ] `bypassPermissions`

> Plan mode is read-only exploration and planning until you approve. acceptEdits auto-approves edits, bypassPermissions skips prompts, dontAsk denies anything that would prompt.

A long investigation (reading logs, grepping 100 files) clutters the main conversation's context. Which Claude Code feature best keeps the main context clean?
- [ ] A larger `max_tokens` value, so the main conversation has more room for the logs
- [x] A subagent that investigates in its own context and returns a summary
- [ ] Adding the relevant logs to CLAUDE.md so they don't count as conversation history

Which TWO statements about Claude Code's **auto mode** are correct?
- [x] It runs without routine permission prompts
- [x] A background classifier reviews actions like shell commands and network requests
- [ ] It behaves exactly like `bypassPermissions`, without any additional checks
- [ ] It disables all configured hooks for the duration of the session

### d3-cc-09
skill: 3.1
type: single
A program needs to send several user messages into one running Claude Code process over stdin and receive events as they happen. Which flags support this?
- [ ] `--output-format text --continue`, sending each message as a new process
- [x] `--input-format stream-json` together with `--output-format stream-json`
- [ ] `--bare --max-turns 1`, restarting the process for every incoming message
- [ ] `--json-schema`, which accepts a schema describing the incoming messages
> Streaming input (`--input-format stream-json`) accepts newline-delimited JSON messages; streaming output emits events line by line. This is the bidirectional streaming mode the Agent SDK builds on.

### d3-cc-10
skill: 3.1
type: single
CI runs of `claude -p` behave differently on different runners because each machine has different user-level hooks, plugins and CLAUDE.md files. What helps make runs reproducible?
- [ ] `--continue`, so every run continues the same reference session on each runner
- [x] `--bare`, passing needed configuration explicitly (`--settings`, `--mcp-config`, …)
- [ ] `--permission-mode bypassPermissions`, so local permission rules can't differ
- [ ] Deleting the repository's CLAUDE.md so only user-level files are used everywhere
> Bare mode skips auto-discovery of hooks, skills, plugins, MCP servers, memory and CLAUDE.md, so only explicitly supplied configuration applies.
