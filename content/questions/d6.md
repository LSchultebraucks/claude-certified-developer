### d6-ctx-01
skill: 6.1
type: single
An agent's `fetch_customer` tool returns the full 18,000-token CRM record on every call, although the agent only needs name, plan and open tickets. Context fills quickly. What is the best fix?
- [ ] Enable compaction every two turns so the large records are summarized away quickly
- [x] Return only the needed fields (with an option to request more) — prune at the source
- [ ] Switch to a model with a larger context window so the records fit comfortably
- [ ] Instruct Claude in the system prompt to ignore all irrelevant fields in the record
> The cheapest, most effective fix is token-efficient tool output. Compaction or larger windows treat symptoms; asking Claude to ignore data still pays for the tokens and dilutes attention.
